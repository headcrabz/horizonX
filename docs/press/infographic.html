What HorizonX Gives You
🛡️ 7-Layer Spin Detection
Six in-session layers + one cross-session layer catch every failure mode: exact loops, edit-revert cycles, score plateaus, tool thrashing, semantic stagnation, and goal-graph standstill across sessions.
ExactLoop BucketedHash EditRevert ScorePlateau ToolThrashing SemanticProgress CrossSession
💾 Crash-Safe Dual-Write
Every step — tool call, observation, error — is persisted to SQLite WAL before the next action executes. Kill the process at any moment and resume exactly where you left off using native agent session IDs.
WAL mode ThreadPoolExecutor Session Resume JSONL Trajectory
💰 Budget Governance
Slack alert at 75% spend. Hard stop at 100%. Per-run AND per-workspace daily limits. Cost velocity detector fires when $/min rate doubles twice in succession — before the runaway costs real money.
75% HITL alert Per-workspace caps Velocity runaway Real Slack Block Kit
🧠 Cross-Run Memory
Agents write facts to workspace/knowledge/*.md. After each session, HorizonX indexes them via FTS5. Future runs receive the top-K relevant facts injected into their session prompt automatically.
FTS5 indexed Relevance-ranked Cross-run persistent YAML frontmatter tags
🎯 Structured Goal Graph
Tasks decompose into a DAG of goals. Agents propose completion; validators accept. Status is monotonic: PENDING → IN_PROGRESS → DONE. LLM-driven re-decomposition on operator request.
DAG topology Validator gates re_decompose HITL Privilege split
🔌 Pluggable Everything
Strategies, agents, and validators are all registered via Python entry-points. Ship a pip package and your agent type works everywhere HorizonX runs. SDK driver for API-based agents (no subprocess needed).
horizonx.agents horizonx.strategies horizonx.validators SDKAgent
